## QMK for Mouse？开源固件的技术野心

根据官方信息，Keychron 此次发布的开源固件基于其在键盘领域积累深厚的 **QMK / VIA** 生态进行扩展。对于熟悉客制化键盘的玩家来说，QMK 几乎等同于"可编程"的代名词——它允许用户重新映射按键、编写宏、自定义层（Layer），甚至实现 RGB 灯效的精细控制。

将这一理念迁移到鼠标上，意味着什么？

### 硬件抽象层（HAL）的重构

鼠标固件的开发复杂度远高于键盘。除了按键，还有：

- **光学传感器（Sensor）**：如 PixArt PMW3360、原相 PAW3395 等，需要处理 DPI 切换、轮询率（Polling Rate）、静默高度（LOD）、角度捕捉（Angle Snapping）等参数。
- **微控制器（MCU）**：通常基于 ARM Cortex-M0/M4，需处理 USB HID 报告、无线协议（如 2.4G / Bluetooth）、电池管理。
- **RGB 与 OLED**：部分高端鼠标带有屏幕或灯带，固件需驱动这些外设。

Keychron 的开源固件很可能采用模块化设计，将传感器驱动、无线栈、HID 报告等解耦，让开发者可以方便地适配不同硬件。

### 用户可配置项的爆发

传统游戏鼠标的配置文件通常被锁死在厂商的驱动软件中（且仅限 Windows）。开源固件的核心理念是：**配置与硬件解耦，逻辑存储于设备本身**。

这意味着玩家可以：

```c
// 伪代码示例：在 QMK 风格固件中自定义鼠标按键映射
void matrix_scan_user(void) {
    // 将侧键 MOUSE_5 映射为 Ctrl+Shift+Tab

        register_code(KC_LCTL);

        register_code(KC_TAB);
    }
```

甚至可以针对不同应用（Photoshop、Excel、CS:GO）配置不同的 DPI 档位和按键行为，通过板载存储（EEPROM/Flash）保存，无需驱动介入。
